## 1. 研究范围与题目优先级

本轮对象是第三问：在场景 B 上加入共享只读 FIFO L2。前两问的方法仅作为可复用构造与已验证的机制，不以其历史答案作为求解输入。题面、附件固定配置和原评估流程约束全部实验；用户提供的工程方案属于启发，不能新增题目未规定的硬约束。

正文围绕“硬件机制—决策变量—合法约束—计算模型—算法—结果解释”展开，不写成基线部署日志。不过题面明确要求无 L2 对照，这部分仍须保留；可称为“无 L2 配置”，不能为了行文删去对照或掩盖比较对象。

## 2. 固定硬件与可控决策

| 项目 | 本题确定口径 |
|---|---|
| 场景 | 沿用 B：每核全部子图合为一个 Task |
| 同核复用 | 同核依赖可驻留 L1/UB，容量不足时由附录算法处理换入换出 |
| 跨核依赖 | 源 COPY_OUT 完成后，再等待 500 cycles，目标 COPY_IN 才具备释放条件；L2 命中不能免掉这项依赖 |
| 私有容量 | L1=524288 bytes，UB=131072 bytes |
| 共享容量 | 配置给出 1048576 bytes，即 1 MiB；不擅自按十进制 1000000 代入 |
| 带宽 | DDR=60 bytes/cycle，L2=250 bytes/cycle，两个池独立，池内公平共享 |
| 初始状态 | 每次官方评估从空 L2 开始；所有核心同构 |
| 输出决策 | 仅 `node_to_subgraph`、`core_schedules` |

可以改变操作的子图归属、子图分核与合法顺序。不能添加预取操作、伪造等待节点、修改输入依赖、预填 L2、设置核心启动时间、固定缓存条目或选择替换策略。Core0 没有题给的特殊预热能力。

核内顺序由附录算法确定。改变子图顺序只能间接影响各 Pipe 的访问顺序；不能假定后一个子图的所有操作都要等前一个子图完全结束。

## 3. 对工程启发的取舍

1. **完整分量装箱**可以作为并行度充足时的构造，但“严禁切开分量”与“零割集必然最优”不是题目规定。既有 case051 五核原评估已给出完整分量方案 607628 cycles、合法切分方案 253856 cycles，足以否定其普遍最优性。图中的逐边 `2×张量大小` 也不能直接用于场景 A 的扇出搬运统计。
2. **通信内化与局部性**用于降低跨核写回、同步和重复读取。但全放同核可能损失并行度，长期驻留也会增加换入换出。采用实际 L1/UB 容量约束，不将“85%”写为官方约束。若保留安全余量，只作为待标定的候选构造参数，并与不使用余量作小样本比较。
3. **MIP 聚类**可作为小规模聚合图上的辅助候选；不能将一个只包含通信边权、负载的 MIP 宣称为完整带宽争用与 FIFO 调度的精确模型。先用贪心和有限局部改动验证机制，只有确有必要才引入求解器。
4. **预热思想**改为“合法顺序形成的首次填充与后续复用”。领读核心由当前图的依赖、工作量和其他就绪任务决定，不固定为 Core0。不得通过题外预热阶段取得不计入 Makespan 的收益。
5. 经典 LPT 近似界不能未经证明迁移到本题的多 Pipe、缓存、依赖和共享带宽系统；正文只对实际证明的下界或性质给出理论结论。

## 4. FIFO 驻留窗口与带宽模型

记操作图为 $G$，张量为 $x$，字节数为 $b_x$，子图归属为 $p(o)$，分核为 $c(s)$，核心列表为 $\pi_k$。主要目标为原评估器返回的 $T_{\max}$；额外搬运与命中率用于解释及相同 Makespan 时的选择，不引入缺乏标定依据的多目标加权和。

令 $e$ 为按官方处理顺序编号的事件，$t_e$ 为物理时间；同一时间也可能对应多个事件。$Q_e$ 为事件后按插入先后排列的 FIFO 队列。请求 $r$ 在发射事件 $a_r$ 的命中指示为

$$
h_r=\mathbf 1\{x_r\in Q_{a_r-1}\},\qquad
p_r=\begin{cases}\mathrm{L2},&h_r=1,\\\mathrm{DDR},&h_r=0.\end{cases}
$$

一次请求的访问路径在发射时确定。在途未命中请求不会因为另一请求稍后填充缓存而自动改道；本题也没有把同时未命中请求合并成一次 DDR 读取的规定。

队列在官方规定的 COPY_IN 完成事件更新：若键已驻留，不改变顺序；若键不存在且大小可容纳，按 FIFO 从队首逐个淘汰，直到满足

$$
\sum_{x\in Q_e} b_x\le C_2,
$$

再把新项加入队尾。命中不刷新 FIFO 排名，不能使用 LRU 或“最近访问后固定存活多久”的模型。原代码 `retire` 对完成的 COPY_IN 调用插入函数，因此还须覆盖在途访问期间条目被淘汰等边界事件，不能只按静态访问列表猜测驻留状态。

对同一逻辑张量的第 $j$ 段驻留，记插入和淘汰事件为 $e^{in}_{x,j},e^{out}_{x,j}$，定义

$$
\mathcal W_x=\bigcup_j[e^{in}_{x,j},e^{out}_{x,j}).
$$

命中由发射时的队列状态决定。绘图可以把事件映射到时钟轴，但同刻插入、淘汰、发射的先后仍须保留。窗口起点是完成填充的事件，不是首次发射或张量首次被计算使用的时刻。一个张量可以被淘汰并重新进入缓存，不能默认只有一个窗口。

带宽工作量用与官方一致的归一化周期表示：对单张量 COPY，请求独占对应池时的工作量为

$$
w_r=\max\{1,\lceil b_r/B_{p_r}\rceil\}.
$$

一个池内有 $N_p(t)$ 个正剩余工作量的请求时，每个请求按速率 $1/N_p(t)$ 消耗归一化工作量。积分表达可用于解释共享服务，但实际完成时刻还受并发变化、取整、Pipe 队首、依赖与内存条件影响，须按原离散事件评估器推进。因此不将单个“时间戳积分闭式公式”冒充完整精确求解器。

第二问中的“全部搬运字节除以 DDR 带宽”不再是第三问通用下界，因为命中字节由另一带宽池服务。第三问必须重新证明剪枝条件；首版优先保留纯计算关键路径、计算 Pipe 负载等安全下界，不因沿用失效剪枝而排除合法优解。

## 5. 拟采用的算法结构

**输入诊断。** 沿用全体 100 例的无损结构统计，新增按逻辑张量统计的共享消费者数、共享输入字节数、跨核潜在读取量及输入聚合规模。观察对象是实际 tensor id 与 size，而不是按普通边数近似通信量。

**冷构造。** 每个 case、每种核数独立从原图生成少量方案：分量装箱、通信紧密组的同核复用、并行度足够的结构切分。复用前两问中纯粹依赖当前输入的构造函数，不载入前次求解计划，也不先执行一轮隐藏的长时间第二问优化。

**合法错峰。** 对存在共享输入的子图组，检查能否利用其他真实就绪工作先占用某核的读取管道，使另一核先完成填充、后续读取落入驻留窗口。不会为提高命中率而强制额外等待；若完成时间更差，就拒绝该改动。

**事件反馈。** 根据一次官方评估产生的真实 miss/hit/insert/evict 和操作时间线，区分首次同时未命中、容量淘汰、关键路径等待、DDR 争用与缓存换入换出。对少数高影响组进行合法相邻换序或整体分核调整，并立即检查全局执行依赖是否有环。

**有限改进。** 同一次调用内保留已经验证的最好可行方案；固定候选预算、去重、无改善停止。代理指标只用于排序，不当作成绩，也不把高命中率等同于更小 Makespan。正式调用预算在小样本验证后冻结，保证初始化评估也计入预算。

工程问题的核心是决定“哪些读取应被同核消除，哪些读取值得跨核并行并由 L2 复用，以及如何让这些读取在合法时序中发生”。不是单独追求零割集、最大命中率或核心负载平均。

## 6. 已完成的规则探针与计划中的验证

`check_rules.py` 使用极小的合成图，硬件参数完全采用附件固定值。它们不是正式 case，不计入 100 例成绩。结果记录在 `rule_probe_results.json`：

- 两核同时读取同一 600-byte 张量：2 次未命中、0 次命中。按核心编号先发射不会自动形成预热。
- 同一张含有额外独立分支的合成图，两种合法顺序：共享输入优先时 127 cycles、0 次命中；另一输入先读时 120 cycles、1 次命中。这里只证明可行机制，不能外推为平均收益。
- 上述错峰方案的无 L2 评估为 127 cycles，因此在这个固定方案上能分别观测硬件配置收益。
- 重复调用官方第三问评估函数返回相同完整结果，表明不继承上一调用的缓存状态。
- 同一方案有/无 L2 的官方 `data_movement_bytes` 字段相同，而命中字节为正。该字段按构造的 COPY 与换入换出统计，并未扣除命中字节；论文须原样报告，并将另外计算的实际 DDR 路径字节量列为单独诊断。

后续先补齐 FIFO 淘汰、命中不刷新、在途重复请求、同刻事件以及“命中改善但时间变差”等规则/反例检查；再用按结构和共享输入特征选择的少量开发例筛选算法。确认样本与开发样本分开，参数冻结后才进入全量。新增实验必须记录当前输入与参数哈希、真实评估调用次数、异常原因和耗时。

## 7. 主对照与统计：待确认

推荐主对照固定同一份第三问方案 $P_{i,n}$，分别调用原问题二和问题三评估器：

$$
R_{i,n}=\frac{T^{B}_{i,n}(P_{i,n})}{T^{L2}_{i,n}(P_{i,n})},\qquad
\overline R_n=\frac1{100}\sum_{i=1}^{100}R_{i,n}.
$$

这表示指定调度方案上的 L2 配置收益；因为方案可能针对 L2 设计，不把该比较称为对任意算法均成立的收益。分别独立优化两种配置可作为补充，展示允许重新设计调度后的系统性能，并明确其中包含调度变化。

无 L2 对照使用原问题二评估器和相同固定配置，不通过修改第三问缓存容量为零制造新“官方配置”。所有 1～5 核都实际执行两种配置；第三問的单核缓存收益不能擅自定义为 1。可以采用同一整图单核时间作两条核心扩展曲线的共同参考，但须与上式同核 L2 收益分开命名。

命中率采用官方按字节定义：

$$
H=\frac{B_{hit}}{B_{hit}+B_{miss}},
$$

分母为零时遵循官方返回值 0。附录逐例保留两种配置的 Makespan、官方额外搬运量和缓存命中率；无 L2 不具有该缓存指标，标为不适用。跨例平均命中率与汇总字节命中率不是同一统计量，需要分别注明，不能混用。
