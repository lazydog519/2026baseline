# 问题一、二：独立输入与约束边界审计

## 判断

当前两问是从输入图重新构造方案的确定性启发式算法，未发现按 case 编号查表或读取历史解。它们具备处理新图的能力，但**尚不能称为泛化性能已经验证的模型**：候选规则和参数曾在题目给定的 100 图上反复开发，原有全量结果属于开发分布上的验收成绩。

本次只测试冻结版本，不改求解器、不用测试结果调参、不更新原 100 图成绩。新图完全由本目录生成器构造，没有从原图抽取子图或拟合图结构分布。官方评估只在两问全部完成方案生成、记录文件哈希后执行。

## 发现一：输入分析有结构依据，但性能估计存在缺口

问题一已经从当前图提取操作依赖、拓扑层、弱连通分量、分支与汇合关系，结合双管道负载、张量大小生成不同切分；不是仅按输入文件名选择预存答案。新分层图中，它分别选择 `mask_sink_2_ready_schedule` 与 `mask_sink_4_ready_schedule`，表明结构候选与任务重排可以在未参与开发的图上发挥作用。

但问题一的时间代理没有显式估计动态缓存溢出，带宽竞争也仅以总字节数等量近似；直接操作边的 `data_size` 未纳入其张量字节统计。完整分量装箱和若干构造函数还把非 M 管道归入另一负载分量。它们是模型适用边界，不能因为操作依赖合法就认为实际耗时也被精确描述。

在首轮共享输入图的五核测试中，问题一最终选择比同场景的固定分量装箱对照慢 0.66%。这是一项代理选择误差，不能删去后再报告算法总是改善。

## 发现二：第二问对编号与输入列表顺序不够稳健

同一个不规则图仅做 ID 双射和数组重排，计算周期、字节数及依赖保持不变，第二问却从 `band` 改选 `data`。不能直接将重编号前后时间差全部归因于求解器，因为官方核内调度也可能使用 ID 打破并列。因此本次还把原方案的操作 ID 作相同映射，保留原来的分组和核心序列，再在同一重编号输入上验收：

| 同一重编号图上的方案 | 官方 Makespan / cycle |
|---|---:|
| 原方案的等价映射 | 168070 |
| 重新求解得到的方案 | 195740 |

重新求解方案慢 **16.46%**。这定位到了候选构造或选择对编号/列表顺序的敏感性；本轮同时改变了编号和列表顺序，尚未将两者的影响分别识别。该现象不是记忆 case 的证据，但说明输入表示变化可能影响算法质量。四个等价变换测试中，问题一未出现相对于映射对照的耗时差异，仍不能由四例证明严格同构不变。

## 发现三：第二问的相对优势没有推广到新分层图

以下是在完全相同输入图和五核配置下，各场景独立求解后由对应官方评估器给出的实际耗时，数值越小越好。

| 非 COPY 操作数 | 问题一 / cycle | 问题二 / cycle | 问题二/问题一耗时 | 问题一生成时间 / s | 问题二生成时间 / s |
|---|---:|---:|---:|---:|---:|
| 576 | 773238 | 2318992 | 2.9991 | 0.4040 | 0.0312 |
| 1152 | 1563459 | 4172607 | 2.6688 | 0.8077 | 0.0552 |

两个图的问题二都选了 `data`。问题二只比较五类结构，问题一还包含掩码切分、就绪列表重排等构造；第二问的评分又额外使用固定缓存风险系数 10。当前证据足以否定“第二问在新图上必然优于第一问”，但尚不足以把差距全归因于候选范围、风险系数或场景缓存机制中的某一项。需要在后续开发中做有针对性的消融，不能根据这两个反例直接回调参数并继续把它们称为独立测试。

首轮 16 个原始图—核数组合中，问题一、二的平均 `分量装箱耗时/所选方案耗时` 分别为 1.0591、1.0379。这是小型机制测试中的对照效率比，**不是题目单核参照加速比，也不是原 100 图的均值**。

## 发现四：提交合法不等于前置校验完整

依据附件 `official/README.md`、`evaluation_validation.py` 和 `stub_multicore_cut_and_schedule.py`，输入要求 ID 唯一、cycles/size 非负、边不重复且完整图无环；方案还要求子图编号为非负整数且不能为布尔值，节点和子图覆盖唯一。

本次注入重复 ID、负 cycles、重复边、仅经 COPY 节点闭合的原图环，官方输入校验均拒绝；两问当前入口仍能生成方案。内部 `validate` 也未拒绝负数或布尔子图 ID，不过能拒绝操作缺失和联合顺序环。**这些是故意注入的非法输入/方案，不是本次 44 份正常输出中出现了非法编号。** 当前生成器实际产生的是非负整数编号，全部已测合法图输出均获官方验收。

因此，原有合法附件上的成功记录依然成立，但求解入口尚未完整实现附件输入契约。对未知来源输入，应该增加独立于官方评估器的轻量检查：完整图字段和类型、全 ID 空间唯一性、边端点/重复边、全图 DAG、参数正值和范围、输出编号及覆盖检查。输入校验不执行性能模拟，不违反求解与官方验收分离的口径。

## 后续处理顺序

1. 先补独立输入/输出契约检查。非法输入应明确失败，不能把它们送进优化器；现有求解规则可先保持不变。
2. 对并列节点采用结构和资源特征决定优先级，减少 ID 和数组顺序影响；但不能声称简单换一个排序键就能保证任意图同构不变。用独立新种子再验证。
3. 针对问题二检查候选覆盖和评分失配，再决定是否纳入问题一有效的结构构造。避免以给定 100 图的平均分为唯一调参目标。
4. 将本次图集转为开发诊断集；今后的确认测试必须重新生成并冻结新种子及结构组，按结构家族留出。报告按图类型分组的成功率、耗时和最差退步，而非只报一个总均值。

“case 是黑箱”在这里意味着求解前没有该图的历史答案；输入到达后，读取其拓扑、张量和资源属性正是算法应做的分析。冷启动解决了历史解依赖，独立留出实验才用于评价泛化，两者不能互相替代。本轮判断是：**可复用的结构求解能力存在，硬件规则下的已测输出可执行；输入防护与问题二稳定性未达到可以宣称可靠泛化的程度。**
