# 问题三：输入图自适应求解

本轮允许在开发阶段使用官方评估反馈诊断模型，但每次验证都从原图重新生成方案。最终方案的生成与官方验收分开。solver.py、engine.py、graph_model.py、baseline.py、q1_optimized.py 和 policy.json 是纯推理文件；其余脚本仅供实验、审计、包装和论文作图。

输入只包括当前计算图、核数和原版 config.txt。没有按 case 编号、文件名或图指纹查表的分支，没有读取历史答案。图指纹仅由外部实验脚本用于文件完整性检查。每次调用都重新建立弱连通分量、计算深度、双 Pipe 工作量和张量生产/消费关系，生成至多十种结构构造，并用资源模型在本图上排序。固定全局配置保存在 policy.json，最终版本为 q3-adaptive-v2-frozen。

模型显式处理跨核 COPY 的 500 cycle 释放延迟、四条 Pipe、60 bytes/cycle 的共享 DDR 带宽、250 bytes/cycle 的独立 Cache 读带宽及 1048576 bytes 的 FIFO 容量。只有 COPY_IN 按逻辑张量标识查缓存。插入发生在读完成时；已经存在的条目不重排。附件会在每次 COPY_IN 完成时尝试插入，因此在途命中条目若曾被淘汰，也可能在完成时重新插入。本轮的轻量模型保留这一细节。

轻量事件图使用自己的拓扑顺序和 Pipe 顺序近似，未复制官方 Step 1–3 调度器。L1/UB 换出量由逐核顺序的驻留/下一次使用估计得到，用于时间校正，不是硬容量证明。原版评估程序负责在冻结后检验真正的核内换入换出和最终执行约束。代理图中的每个事件都只是模型内部变量，不向原图添加操作，也不输出指定起始时间、额外预热或人为等待。

开发样本由当前图的节点规模、连通分量和固定哈希次序预先抽取。首轮开发四图为 development_split.json 所列，另四图用于本轮确认。六个全局换出权重的敏感性比较复用同一批已冻结候选标签，不重新枚举运行；最终选中单位系数 1。由于历史迭代已查看给定数据，本轮确认和全量成绩都不被写成完全未见分布的泛化证明。开发数据与失败记录保留。

独立调用：

    python solver.py 输入图.json -n 5 --config 原版config.txt -o 输出方案.json --report 本次诊断.json

单核使用整图固定方案，不开展搜索；L2 与无 L2 的单核执行时间仍由官方程序对照，不能把单核缓存收益预设为 1。

full5_v2/：100 图、5 核；full1to4_v2/：100 图、1～4 核。每个目录的 generation_manifest.json 冻结输入、代码、配置和输出哈希。先完成 run.py generate，再执行 run.py audit。若中断，确认没有相同目录的进程后用相同命令加 --resume，已完整匹配的记录跳过，未完成的生成任务重新启动进程求解。不得读取旧方案作为优化初值。

full5/ 是首轮开发诊断结果，五核均值 4.119956，不是最终版本。其源码保存在 v1_source/。首轮发现同核子图表达和切分粒度会影响候选排序，因而向所有输入统一补充同核合并、双倍深度带两个候选；没有为某个 case 添加专属分支。confirmation_v2/ 是最终版本八图确认。所有最终用例均在补充候选后重新冷启动生成，不能把不同版本各例的最好成绩拼接成全量结果。

对同一方案，results/ 保存无 L2 与只读 Cache 两份原版结果。cache_gain 定义为无 L2 Makespan / 只读 Cache Makespan；l2_speedup 使用题面原始单核基准。二者是不同指标。与问题二冻结算法的比较独立列出，避免把调度改变的收益全部归因于 L2。

论文沿用前两问的 $G=(T\cup O,E)$、$\phi$、$a$、$\pi_k$、$T_{i,N}$、$D_{i,N}$ 和 $S_{i,N}$。新增 $C_{\mathrm{L2}}$、$\beta_{\mathrm{L2}}$、FIFO 队列 $\mathcal Q(t)$、缓存加速比 $R_{i,N}$。总额外搬运量与实际 DDR 通道服务字节不混为一谈；命中字节和命中率按官方字段报告。

全量验收结束后运行 `python finalize.py` 汇总两组最终目录，输出 final/aggregate.json、final/metrics.csv，更新论文结果段并生成两组 PNG/PDF/SVG。该脚本不调用评估器或重新求解。`python package.py` 打包六个纯推理文件，并用隔离目录中的改名输入核对复现。

从项目根目录重新生成一组独立结果的示例（新输出目录；不要覆盖已冻结结果）：

```powershell
python q3_adaptive_20260926/run.py generate --output q3_adaptive_20260926/replay --cores 2 3 4 5 --workers 4
python q3_adaptive_20260926/run.py audit --output q3_adaptive_20260926/replay --workers 4
```

已完成的官方验收只证明这批输入上的合法性。未来同格式图仍需独立验收；核内换出近似和有限候选不构成所有未知图上成功率或最优性的数学保证。

`python export_plans.py` 将已冻结方案按附件的 `<case>_multicore_res.json` 命名打包到 final/plans_q3.zip，各核数分目录保存；不重新求解或评估。
