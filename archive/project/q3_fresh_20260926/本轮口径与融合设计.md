# 本轮口径与问题三融合设计

本轮版本：`fresh-q3-20260926-v2`。定位：小规模方法验证，尚未成为全量提交版本。本轮未读取旧项目的方案、成绩、搜索轨迹或训练参数；旧版 4.395999 不能作为本版本成绩。

## 1. 训练、求解与验收的边界

开发阶段可以调用未修改的官方评估器，形成训练标签、分析失败原因和调试算法。冻结后，求解器只读取当前原图、原始硬件配置和本轮训练得到的通用参数，从头构造并选择方案；其代码不含官方评估器的导入或调用，不读取历史方案、成绩和缓存。模型参数对所有输入共用，不能按 case 名称、文件路径、图指纹或节点编号模式查表选答案。

同一次求解内部，从当前图生成候选并继续改进候选，是正常优化，不属于读取历史答案。保留 LPT、依赖图、资源守恒等通用知识也不违反冷启动。真正需要隔离的是特定实例的历史状态，以及本轮之外的经验参数。冷启动本身不等于泛化：若在某图的评测结果上调过参数，该图就不能继续作为未见测试样本。

本轮数据流为：原始图 → 冻结训练候选 → 官方标签 → 通用参数冻结 → 隔离进程生成留出图方案 → 方案哈希冻结 → 独立官方验收。验收结果不反馈给该次求解重新选择方案；若据其诊断改进方法，则形成新版本并更换留出样本。

## 2. 对参考论文的取舍

依据：用户提供的《通用神经网络处理器下的多核切图与协同调度优化模型与算法》，题面问题三及附录 B～D，附件 `official/README.md` 与对应源码。参考论文的经验方向有价值，但以下论断需要修正。

| 参考论文内容 | 本轮核对与处理 |
|---|---|
| 第 4 页：并发 DDR 导致总时间二次方恶化 | 等大小的 n 个搬运同时共享带宽 B 时，各自完成于 nS/B，总完工时间也是 nS/B；n²S/B 是完成时间之和。不能用后者代替 Makespan。保留带宽守恒，舍弃二次方完工时间论断。 |
| 第 5 页：计算时间、总 DDR 停顿与全部边等待相加等于 Makespan | 计算、搬运及不同路径等待可以重叠。依赖等待沿一条路径累加，再对路径取最大值；全图所有边的等待不能直接相加。 |
| 第 5～6 页：零割集保证零新增搬运，LPT 有全问题近似比 | 分量完整性可以消除计算分量之间的切边，仍可能有跨核重复读取和缓存换出。经典标量独立作业 LPT 的界不直接覆盖多 Pipe、共享 DDR、缓存和通信耦合后的 NPU 问题。 |
| 第 7 页：85% 余量保证永不 Spill | L1、UB 必须分别核算；0.15×128 KiB=19.2 KiB，不能套用 76.8 KiB。需要统计实际分配顺序与输入输出同时驻留；静态近似峰值和任意固定比例不能证明实际零 Spill。 |
| 第 9 页：所有 COPY_IN 发起量决定精确 FIFO 淘汰时刻 | 只有成功的缓存插入改变 FIFO：未命中读完成后才插入，命中不重排，重复插入和超容量对象也有特殊处理。仅累计发起请求会把未完成读取和命中错误计入。 |
| 第 9～10 页：Core 0 在时刻 0 预热、消费者按窗口指定发射 | 输出接口只有操作归属和子图顺序，没有显式发射时间、额外预热操作或等待指令。只能通过合法划分、分核和顺序间接影响实际时序，不能把无法提交的控制变量当成已实现功能。 |
| 第 24～27 页：程序实现了窗口对齐 | 附录代码收集了共享输入，但 `solve()` 的主要分支仍是分量装箱、链分配和深度分层；没有对应正文所称的精确窗口求解调用。论文描述和代码需要一致。 |

重新扫描原始 100 图，得到 84 图弱连通分量数不少于 4、16 图只有一个弱连通分量、97 图存在被多个计算操作消费的输入张量，与文中的结构计数吻合。但“多个算子共享输入”不等于“最终方案一定跨核共享”，后者取决于本次核心分配。

这些核对并不意味着调用评估器开展开发实验违反题目。本轮将最终求解与评估隔离，是用户确定的额外交付要求；不能把它写成题面没有明文规定的禁令。

## 3. 从原图重新构造的工程决策

保留四种由当前图现场构造的结构策略：标量分量装箱、Cube/Vector 双管线分量装箱、独立前缀与规约尾部分离、共享前驱与独立输出枝分离。各策略使用当前图的依赖和周期，没有按算例编号分支。重复方案按内容去重，最多四种结构，不进行大规模参数枚举。

子图商图及“子图依赖 + 同核顺序”必须无环，操作恰好覆盖一次，每个非空子图恰好分配一次，空核心用空数组表示。原图和题面参数不修改。本轮还保守地要求核心间依赖图无环，以避免形成跨核等待闭环；这是算法选择的充分结构限制，**不是题面额外硬约束**，也可能排除更好的合法流水方案。

缓存复用通过同核通信内化、受依赖约束的分支结构和重复读取特征参与决策。FIFO 的真实命中、实际 Spill 和最终执行时间仍是验收输出。本原型不宣称已实现精确 Cache 时间窗口调度。

## 4. 物理下界约束的通用预测模型

令方案为 π，c(o) 为算子所在核，p(o) 为 Pipe，t(o) 为给定计算周期。对两条计算 Pipe 分别累加负载，得到

\[
L_{\mathrm{pipe}}(\pi)=\max_{c,p\in\{M,V\}}\sum_{o:c(o)=c,\,p(o)=p}t(o).
\]

沿原计算 DAG 的路径 P，将跨核依赖必需的同步延迟 500 cycles 纳入：

\[
L_{\mathrm{path}}(\pi)=\max_P\left[\sum_{o\in P}t(o)+500\sum_{(u,v)\in P}\mathbf1\{c(u)\ne c(v)\}\right].
\]

Cache 初始为空。对有消费者的输入逻辑张量，至少发生一次 DDR 读取；对需要跨核传递的计算结果，至少发生一次写入和一次读取；最终结果至少发生一次写入。按逻辑张量去重，不按每条投影 Op 边重复计费，得到本构造族的必需 DDR 字节下界 D_min。其他消费者可能命中缓存，因此不把其重复读全部当成必需 DDR 流量。

\[
L(\pi)=\max\{L_{\mathrm{pipe}},L_{\mathrm{path}},D_{\min}/60\}.
\]

构造特征 f(π)，各项均以 cycles 表示：物理下界、跨核路径搬运暴露、读写流量代理、共享输入重复读暴露、分别按 L1/UB 计算的逻辑驻留超额量除以带宽。最后一项采用候选顺序中的定义—最后使用区间，计入同一操作输入输出同时存在；它仍不等于附件的实际多 Pipe 分配顺序，不能作为实际缓存峰值证明。

代码字段 `compulsory_io` 是 v1 沿用的特征名称，表示扣除可重复共享输入后的流量代理，**不是严格下界**；严格的字节下界单独保存在 v2 的 `minimum_ddr_bytes`，仅后者参与物理下界。

用本轮官方标签学习所有算例共用的非负系数 w，并固定预测形式：

\[
\widehat T(\pi)=\max\{L(\pi),w^\mathsf T f(\pi)\},\qquad
\pi^*=\arg\min_{\pi\in\mathcal C(G,n)}\widehat T(\pi).
\]

按每张图共同的物理规模归一化标签和特征，采用非负岭回归，固定正则系数 0.01。五个系数仅从本轮 6 个训练图的 17 份冻结方案标签拟合。它们不是针对个别 case 的参数。模型即使将某个统计特征权重拟合为零，也不能越过 L；零回归系数不代表该物理机制不存在。

在这一规模下不需要 GPU 或大型神经网络。更复杂的进化搜索要建立在可信的候选排序能力上，否则只会更快地利用代理误差。

## 5. 本轮实验与失败记录

样本根据本轮重新提取的图结构选取，未使用旧成绩。首轮训练图为 029、040、046、007、048、082，均为小中规模图；首次留出图为 055、013、088。首轮只用回归评分时，3 图中 2 图退步，不能接受。其中 case 013 的方案必需搬运明显增加，但模型忽略了该资源瓶颈。首轮结果完整保留在根目录 `summary.json`，没有删除失败记录。

v2 的修正是加入上述物理下界，不添加针对 case 013 的例外规则。沿用**同一轮刚生成的** 17 个训练标签，重新计算特征和拟合；不读取以前项目的训练经验。首次留出图已用于诊断，因此 v2 用另外 3 张图进行独立验收：

| 新留出算例 | 分量贪心 Makespan / cycles | v2 Makespan / cycles | 相对缩短 |
|---|---:|---:|---:|
| case 024 | 2,555,343 | 2,538,813 | 0.647% |
| case 083 | 310,731 | 310,731 | 0.000% |
| case 069 | 25,144 | 11,234 | 55.321% |

v2 在这 3 图的五核下，同一方案开启 L2 的加速比均值为 1.145600；相对原始单核参考的平均加速比为 2.216523。二者分母不同，不能混用；这两个数都不是全量 100 图成绩，也不能与旧方法 100 图均值直接比较。三个样本不足以证明普遍占优，特别是大图、复杂缓存换出和多核数下的预测质量尚未完成官方测试。

两轮合计 45 次官方调用，包括训练、对照和单核参考验收；提交求解过程的官方调用数始终为 0。v2 六份“方法 × 留出图”输出均在隔离目录、改名输入、新进程下重复生成一致，之后才开始官方验收。官方附件 114 个文件 SHA-256 未变，全部观测到的下界均未超过相应官方 Makespan。这里只能称为有限实验核对，不能代替一般数学证明。

## 6. 文件和使用方式

- `solver_v2.py`：当前独立求解原型，只导入 Python 标准库。
- `v2/model.json`：本轮通用权重，不包含 case 方案或分数表。
- `v2/submission_prototype.zip`：仅含求解器和参数文件，不含评估器、图数据、训练标签或历史方案。
- `manifest.json`、`training_labels.json`、`v2/manifest.json`：本轮数据来源、划分和冻结哈希。
- `v2/generation_freeze.json`：全部验收方案在验收前冻结的证据。
- `v2/validation_results.json`、`v2/summary.json`：真实官方验收结果。
- `screen_structure.py`：100 图 × 1～5 核 × 4 种构造的纯结构检查；不计算官方成绩。

解压代码包后运行：

```powershell
python solver.py 输入图.json -n 5 --config 原始config.txt --model model.json
```

输出为同目录下 `输入图_multicore_res.json`，顶层严格只有 `node_to_subgraph` 和 `core_schedules`。推理本身无第三方包依赖。本原型以题面固定配置训练；尚未证明对其他硬件参数的预测泛化。

当前完成了用户要求的训练/求解隔离，并得到有限正面样本证据。下一阶段应先扩大结构覆盖和按图族划分的验证，确认低估误差、失效类型与大图成本，再决定是否增加局部搜索或开展全量官方评测。未经这些验证，不把该原型替换为正式提交主版本。
