# 问题一：无核间同步条件下的切图与调度

## 题意与计算口径

场景 A 中，一个子图恰好对应一个 Task。同一核心切换 Task 时，私有缓存状态被清空；因此只要张量跨越子图边界，即使两个 Task 位于同一核心，也须经 DDR 写回和读入。每个非 `COPY_IN`/`COPY_OUT` 操作必须恰好归入一个子图，并给出每核 Task 的串行顺序。优化目标是首先缩短全部 Task 的完成时间，同时控制因切图和内存溢出产生的额外数据搬运。核数取 2、3、4、5；单核仅按题目规定使用整图核内调度时间作加速比的分母参考，其加速比恒为 1。

固定硬件参数直接读取题目配置：DDR 带宽 60 bytes/cycle，同核 Task 切换等待 100 cycle，跨核 Task 依赖等待 1000 cycle，L1/UB 容量分别为 524288/131072 bytes。附件评估器才给出实际 Makespan 与溢出搬运量；下述快速模型只用于生成与排序候选，不将其预测值写成实测结果。

## 符号与决策变量

令原计算图为有向无环图 $G=(V,E)$，$V$ 排除输入输出 COPY 节点；$c_v$ 是操作 $v$ 的计算周期，$p(v)\in\{M,V\}$ 是其 Pipe。张量 $t$ 的大小 $b_t$ 以 byte 计。决策由子图映射 $\phi:V\to S$、核心映射 $a:S\to\{1,\ldots,N\}$、每核子图排列 $\pi_k$ 组成。子图之间的原始数据依赖与 $\pi_k$ 施加的串行边合并后必须无环；这是提交前的结构可行性条件。每个子图在结果中只出现一次，不切开或改写任何原始操作。

以 $P_t=\{\phi(v):v\text{ 产生 }t\}$ 和 $C_t=\{\phi(v):v\text{ 消费 }t\}$ 表示张量的生产和消费 Task 集。对每个消费 Task $s\in C_t\setminus P_t$，插入一次输入搬运；对每个需要给其他 Task 或原输出提供数据的生产 Task，插入一次输出搬运。按 Task 而非按依赖边计数，可避免同一张量在同一 Task 内有多个消费者时被重复计算。记由此形成的总 COPY 字节数为 $B_{\mathrm{task}}$，原图 COPY 字节数为 $B_0$，则切图额外搬运为 $B_{\mathrm{cut}}=B_{\mathrm{task}}-B_0$。官方评估的总额外搬运还含调度器真实插入的溢出搬运：$D=B_{\mathrm{cut}}+B_{\mathrm{spill}}$。快速模型不能预知 $B_{\mathrm{spill}}$ 的确值。

## 工程化候选与排序

完整弱连通分量可作为零割集的装箱物品，先按两条 Pipe 的负载向量做最长处理时间优先的贪心分配。这个构造不会引入分量内部的 DDR 边界，但不能保证总完工时间最小；例如某分量包含宽并行阶段时，保留整块可能使其只能占用一个核心。为处理这种情况，另外沿计算图深度带、宽度谷、汇合点及共享祖先/后继掩码生成有限个切分候选。切分粒度的初值与跨核等待周期、图深和总工作量有关；每个候选都重新检查操作覆盖、Task 覆盖和依赖/核内顺序的无环性。

对结构上较有希望的候选，再尝试一次就绪 Task 的最早完成时间贪心排核，以及至多两步的相邻 Task 合并。合并仅在新的 Task 图仍无环时保留。这样既允许关键路径获得更多并行度，又有机会消除不值得的边界搬运。该步骤是有界的图上搜索，而非用官方评估器枚举选优。

对于 Task $s$，定义两类 Pipe 的工作量 $W_s^M,W_s^V$、输入和输出字节 $B_s^{\rm in},B_s^{\rm out}$。快速时长代理为

$$
\widehat d_s=\max\!\left\{W_s^M,\ W_s^V,\ \frac{B_s^{\rm in}+B_s^{\rm out}}{60}\right\}.
$$

将每个 Task 的前驱完成时间与同核顺序边合并，跨核依赖加 1000 cycle，同核 Task 顺序切换加 100 cycle，得到图上最早完工预测 $\widehat T$；再以全图 DDR 工作量除以 60 cycle 的资源下界修正预测。$\widehat d_s$ 及 $\widehat T$ 不模拟附件中的逐操作发射、共享带宽争用和 Step 2 的内存溢出，因此只用于候选排序，绝非实际 Makespan 的替代值。排序先取最小 $\widehat T$；若分量装箱与最优代理的差距不超过开发阶段固定的 1%，保留分量装箱以避免近似误差触发无意义切图；确需切图时以预测搬运字节数作次序判别。这个 1% 是选择策略参数，不是理论近似比或硬件安全阈值。Graham 单资源 LPT 的近似比不能直接套用于双 Pipe、依赖、DDR 与缓存共同作用的本题。

## 求解、调试与官方验收的隔离

独立推理入口为 `solver.py`。它只读当前图、原版 `config.txt` 和固定全局 `policy.json`，输出恰好两个字段 `node_to_subgraph` 与 `core_schedules`；它不导入官方评估器，不读其他 case 的方案或成绩。每个图/核数在独立进程中从原图重建候选。开发时先冻结候选文件，再用另一脚本 `develop.py` 调用官方评估器标注，依据开发图修正了预测值并列时的选择规则。留出图仅作检查。最终对 100 图 × 2～5 核先完成全部方案和代码哈希冻结，再由独立 `full_audit.py` 统一调用原版程序；若验收失败，记录具体失败图与约束，不更改官方代码或悄悄剔除图。

开发样本由图规模、最大弱连通分量比例、计算深度等**输入结构**事先选取。8 个开发图中，127 个候选均通过原版验收；修正并列判别后的选择规则相对双 Pipe 分量装箱在 3 图改善、0 图退步。4 个预设检查图中，65 个候选均通过验收，最终选择在 1 图改善、1 图轻微退步。并列规则是在开发标注后修正的，检查图的候选标签先前已被查看，因此不能把这 4 图声称为修正策略的严格盲测。这个样本只用于小规模可行性与模型误差诊断，不能替代百例全量指标。
