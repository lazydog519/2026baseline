## 三问设计边界

统一候选只决定原始非 COPY 操作的子图归属、子图分核和各核子图顺序。

- 问题 1 重点平衡并行度、Task 边界搬运与 CPU 主控等待。同核跨 Task 仍清空私有缓存并经 DDR 传递。
- 问题 2 重点平衡核心负载、同核复用、L1/UB 存活量与跨核依赖。不得额外添加“整子图结束才可执行下一子图”的屏障。
- 问题 3 沿用问题 2，并在候选选择中考虑共享输入的访问顺序及 Cache 占用。FIFO、发射时查询、搬运完成时装入、两带宽池和固定同步延迟均保留。

MAGIS 的重计算、运算拆分和图等价变换不属于本题开放的决策。Timeloop 所需的张量维度和索引关系不能从字节大小自行编造。通用搜索结构及复用分析可借鉴，原模型的延迟数字不能作为本题成绩。

## 验收条件

1. 最小题面示例：三问均复现 6 cycles、32 bytes 原始/计划搬运、0 新增搬运；Cache 无命中。
2. 每个方案顶层恰好是 `node_to_subgraph`、`core_schedules`；映射键为操作 ID 十进制字符串；全覆盖、无遗漏、无重复；每个 sgid 恰好调度一次。
3. 基础划分校验、同核顺序校验通过。基础 `validate_multicore_plan` 不等于最终执行可行性，必须继续通过对应评估入口的 Task/Pipe/内存/跨核依赖检查。
4. 最终保留方案全部由原始评测器重新评估；原始代码和 config 的哈希保持不变。表格必须能追溯到评估 JSON，不能把候选近似分数写入最终指标。
5. 核对方案文件、用例、场景和核心数对应关系；检查结果矩阵的缺失、重复、非有限值以及完成节点覆盖。
6. 对关键机制设计小例检查，对代表结果检查 Pipe 串行、依赖和等待；额外检查的范围与限制如实记录，不宣称有限测试证明算法全局最优。
7. 根据真实逐用例数据生成题目要求的曲线、附录表和必要诊断图，核对单位、平均方式、图注与实际代码一致。
8. 提供算法入口、单用例命令、批量运行命令、依赖版本、种子、运行环境、来源引用和 AI 辅助说明；最终附件符合命名与大小要求。
