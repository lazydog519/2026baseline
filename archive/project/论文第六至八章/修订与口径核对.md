## 求解与验收

三问共 16 个冻结源文件与已有运行摘要的 SHA256 一致。提交求解模块的导入依赖均为自身模块和标准库，未引入官方评估器。已有隔离改名输入复现记录表明：Q1/Q2 的 case_010、case_078，Q3 的 case_011、case_078 在独立目录中生成的方案与冻结方案一致。记录见 `data/三问冻结版本核对.json`。本次没有重新耗时运行全量实验。

每个输入图重新计算分量、拓扑和张量关系，有限候选的比较也在本次调用中完成。允许保留的是已冻结的算法和全局参数；不会加载历史逐例方案、用例编号对应表或先前搜索状态。最终方案生成后，才由独立验收程序调用原版附件。

给定的 100 个图参与过开发诊断与参数标定。冷启动说明运行状态独立，不构成对未知图分布的泛化证据。因此文稿将结果限定为本题输入与配置下的表现。单核仅采用固定整图方案，不进行单核搜索；第三问保留单核 Cache 配对测量，因为其耗时可能随 L2 开关变化。

## 硬规则与模型近似

- 原始图按 Tensor–Op 二部图解释。第六章移除了不属于附件输入规范的直接 Op–Op 边项。用于分析的操作依赖由生产者–张量–消费者关系投影得到，原操作、周期、大小和存储位置未改动。
- 场景 A 每个子图分别形成 Task，同核跨子图也要经过 DDR；场景 B 同核子图合为一个 Task，跨核仍有搬运与固定延迟。两章分别保留其规则。
- 输出仅包含 `node_to_subgraph` 和 `core_schedules`。节点覆盖、子图唯一分配以及数据依赖与核内顺序合并后的无环性需要检查。
- L1/UB 容量、共享 DDR 总带宽与 FIFO L2 配置均沿用附件。三问的快速评价属于方案排序模型：Q1 没有展开缓存换出，Q2 的活跃区间是顺序近似，Q3 也未完整复制官方空间复用补边。文稿明确这些误差来源，不将代理峰值写成官方容量证明。
- 第八章区分发射时查询和完成时插入；同时间戳已处理的插入可影响后续查询。每次 COPY_IN 完成都会尝试插入，命中本身不刷新 FIFO；在途命中被淘汰后也可能重新插入。COPY_OUT 不写入只读 Cache。
- 官方额外搬运字节与实际 DDR 服务字节含义不同。本轮同方案开关 L2 的 500 组逻辑搬运量逐项相同，缓存收益体现在服务路径与完成时刻。

## 文字与伪代码修订

第六章补清了候选生成、去重、原始前三候选选择、独立重排及合并的顺序，避免把多种变换写成连续迭代。保留经典 LPT 与列表调度的思想来源，但未把经典近似比直接套用到共享带宽、容量约束的本题。

第七章补充深度尺度的取整规则、通信字节计数范围、驻留风险的近似含义和去重集合更新步骤。风险比中位数为 10.54，实际使用的全局系数为 10；原先“取整得到 10”的不准确表述已改为开发选择后冻结。

第八章从数据通路引出候选构造，再给出事件推进与核内驻留修正，两段算法分别承担评价和选择。表 8-1 的十种候选上限、排序时的名称字典序和兜底条件均与源码对应。当前冻结算法是有限候选启发式，未写成未实现的 NSGA-III 或全局精确优化。

段落以规则、推导和证据承接，不在每节重复概括性结论。结果保留退步案例，避免以均值提升替代逐图分析。

## 跨章符号

| 符号 | 定义与单位 |
|---|---|
| `G=(T∪O,E)`、`G_c` | 原始二部图、非 COPY 操作依赖投影图 |
| `c_u`、`b_t` | 操作周期 cycle、张量字节 byte |
| `N`、`k` | 核数、从 0 开始的核心编号 |
| `φ`、`a`、`π_k` | 操作到子图、子图到核心的映射及核心子图序列 |
| `W_j^q`、`L_k^q` | 分量或核心在计算管道 q 上的工作量，cycle |
| `β`、`β_L2` | DDR、L2 总带宽，byte/cycle |
| `w_0`、`w_B`、`w_C` | 当前图推导的拓扑切分尺度，层 |
| `γ_B`、`γ_C` | 第二、三问各自的全局驻留修正系数，无量纲 |
| `T_{i,1}` | 三问共同的原始单核参照完工时间，cycle |
| `S`、`R`、`η` | 相对单核加速比、同方案缓存加速比、耗时缩短率 |

所有加速比先逐图计算，再取算术平均。字节命中率、请求命中率以及总体字节池化后的比值不能互换。表 8-2 报告逐图字节命中率的均值。
