第六章　问题一与问题二的建模和求解

共同的决策与评价口径

原始计算图记为 G=(T∪O,E)，其中 T 和 O 分别为张量与操作节点集合。 令 Oc=O∖{COPY_IN,COPY_OUT}； 对 o∈Oc，co 为题面给定的计算周期，p(o)∈{M,V} 表示其占用的 Cube 或 Vector 管道。张量 t 的大小 bt 以 byte 计， 逻辑位置由原图的 pos 字段确定。对给定核数 N∈{2,3,4,5}， 决策是子图映射 ϕ:Oc→S、核心分配 a:S→{1,…,N} 和每核子图序列 πk。

可行方案必须使每个非 COPY 操作恰好属于一个子图、每个子图恰好在一个 πk 中出现一次；原数据依赖形成的子图图为 DAG，序列 πk 与其依赖顺序相容。输出文件只含 node_to_subgraph、core_schedules 两个字段。 各核共享同一 DDR 总带宽 β=60byte/cycle， 私有缓存容量为 CL1=524288byte、 CUB=131072byte；不能把 β 乘以核数。 官方程序在固定配置下计算实际 Makespan Ti,N 与总额外 DDR 搬运 Di,N。我们以缩短 Ti,N 为主，兼顾 Di,N。 按题目规定，单核整图调度时间 Ti,1 仅作共同参照， Si,1=1，Si,N=Ti,1/Ti,N， S¯N=100−1∑i=1100Si,N。

独立求解与验收协议

两问的正式推理程序均以当前图、固定配置和冻结的全局规则为输入， 对每个图/核数从头生成方案；不读取其他图的方案、逐图成绩或评估器输出。 开发阶段可用官方程序检查模型误差，正式方案全部生成并记录 输入、代码和结果哈希后，再由分离脚本作 100 图全量验收。 因此本章报告的是可重复运行算法的结果，而非保存的逐例答案。 结论只对题目给定数据和硬件配置成立；更换带宽或缓存时，应重新 检查式（6.3） 与式（6.9） 的排序误差。

问题一：无核间同步的场景 A

Task 边界与计算模型

场景 A 中一个子图对应一个 Task。任一张量只要跨越子图边界， 即使生产与消费 Task 在同一核心，也必须经 DDR 写回、再读入； 同核两个 Task 切换时私有缓存清空。以 Is、Us 分别表示 Task s 需从 DDR 读入、向 DDR 写回的不同张量集合， 按 Task 和张量去重后，计划的总搬运量为

(6.1)BA=∑s∈S(∑t∈Isbt+∑t∈Usbt),DA=BA−B0+Bspill,A,

其中 B0 为原图已有的 COPY 字节数，Bspill,A 是附件核内调度在 L1/UB 不足时实际插入的换出、换入字节数。 式（6.1） 区分可由切图直接计数的边界搬运和 只能在正式验收后得到的缓存溢出搬运，避免把二者混作一个预测量。

Task s 在两条计算管道上的工作量分别为 Wsq=∑o:ϕ(o)=s,p(o)=qco，q∈{M,V}。 求解时使用的快速时长代理是

(6.2)d^sA=max{WsM,WsV,∑t∈Isbt+∑t∈Usbtβ}.

设 PA(s) 同时包含数据前驱 Task 与同核序列直接前驱； 前者若跨核取等待 1000 cycle，后者取 Task 切换等待 100 cycle， 其余等待记为 0。在依赖与序列的合并 DAG 上递推

(6.3)F^sA=d^sA+maxr∈PA(s){F^rA+δrsA},T^A=max{maxsF^sA,BAβ}.

空前驱的最大值为 0。T^A 只供候选排序， 并不等于附件的逐 Pipe、多核共享带宽时间线；特别是 Bspill,A 不在该代理中。

零割集装箱与有界结构切分

首先将计算依赖图的弱连通分量 Cj 作为不可切的装箱物品。 记 wjq=∑o∈Cj,p(o)=qco，Lkq 为核心 k 已分配的对应管道负载。按 maxqwjq 降序遍历分量， 每步选取下式字典序最小的核心：

(6.4)kj=arg⁡mink(max{LkM+wjM,LkV+wjV},LkM+LkV,k).

该构造在分量内部不产生通信割，但单个大分量可能独占一核。 式（6.4） 是双管道贪心规则；经典标量 LPT 的完工时间近似界不能直接用于含依赖、DDR 争用和缓存换入换出的本题。 因此仅对原图结构生成有限种补充方案：按图深划带、在宽度谷处分段、 在汇合点前后区分分支、按共享祖先或后继关系聚合。 对最大拓扑深度 h 和总计算工作量 W=∑oco， 初始分段尺度为

(6.5)w0=max{2,⌈1000NhW⌉,⌈Nh256⌉},

并考察 w0,2w0,4w0。式中 256 只是限制候选粒度的 固定计算预算参数，不是硬件容量或题目规定的子图上限。 所有候选均检查操作覆盖、子图覆盖与合并依赖图无环。 代理值最小的至多三个结构候选再分别尝试一次就绪 Task 排核与 至多两步的合法相邻 Task 合并；若代理改进不超过开发阶段固定的 1%，保留分量装箱方案。这是避免代理并列误差触发无谓切分的 防抖规则，不是近似比或性能保证。

算法 1　 场景 A 的结构候选与 Task 排序

**输入：**G，核数 N，题目固定配置；　**输出：**ϕ 与 (π1,…,πN)。

  1. 删除原图 COPY 操作形成计算依赖 DAG；统计 co、bt、图深及两类管道工作量。
  2. 用式（6.4） 装箱弱连通分量，得到零割集候选。
  3. 按式（6.5） 的有限尺度生成深度带、谷点、汇合与共享关系候选。
  4. 对每个候选检查覆盖与无环，计算 BA 和 T^A，记录不可行原因。
  5. 对代理排名前三的结构方案尝试一次就绪排核及有界相邻合并，重新校验和排序。
  6. 若代理收益不足 1%，选分量装箱；否则选代理最小且搬运较少的合法方案。

算法不读取同图历史方案或官方评估值；每个输入图重新执行以上步骤。

全量结果与解释

在固定配置与全部 100 个官方计算图上，先独立生成并冻结 2–5 核各 100 份方案，再调用未修改的场景 A 评估程序，共 400 次验收，均成功。按题面单核参照计算，2、3、4、5 核的平均加速比分别为 1.8648、2.6016、3.2650、3.8311。五核相对纯分量装箱的成对比较中，38 图耗时缩短、2 图耗时增加、60 图不变；因此结构切分并非对所有图都有收益。两场景的核数曲线见图 6-2；逐图 Makespan 和额外搬运量见附录表。

问题二：同核子图合并的场景 B

通信内化与缓存驻留

场景 B 将一个核心上的所有子图合并为一个 Task。 同核生产–消费关系可以直接复用 L1/UB，无需因为子图边界而访问 DDR； 跨核依赖仍需 COPY_OUT/COPY_IN， 并等待固定 δB=500 cycle 的同步延迟。 与场景 A 相比，减少切图边界本身不再自动减少搬运量； 真正决定边界通信的是是否跨核。相反，同核直通会延长 部分张量的驻留区间，可能造成 L1/UB 换入换出。

令 Pt、Ct 分别是张量 t 的生产核与消费核集合， et=1 表示原图要求将其作为最终结果写回 DDR， 1[⋅] 为示性函数。按附件的每个源核–目标核 拷贝规则，溢出前的总 DDR 字节数可写成

(6.6)BB=∑t∈Tbt(1[Pt=∅]|Ct|+1[Pt≠∅]1[et=1orCt=∅]|Pt|+2∑k∈Pt∑ℓ∈Ct1[k≠ℓ])+2∑(u,v)∈EOOduv1[a(ϕ(u))≠a(ϕ(v))],DB=BB−B0+Bspill,B.

式中输入在每个消费核读一次，输出在每个生产核写一次； 跨核生产–消费核对各产生一次写和读。同核核对的贡献为零。 EOO 是原图中直接连接两计算操作的依赖集合，duv 是该边的 data_size；这类边在跨核时也计一次写和一次读。 Bspill,B 仍由附件调度器在严格容量约束下插入， 并不被式（6.6） 的溢出前计数替代。

为给候选快速排序，令 Lkq=∑o:a(ϕ(o))=k,p(o)=qco 表示核心 k 的管道负载。对计算操作间依赖 u→v， buv 为该依赖关联的张量字节数与直接边 duv 之和 （若无直接边则 duv=0）。 沿原操作 DAG 递推

(6.7)F^vB=cv+maxu∈pred(v){F^uB+1[a(ϕ(u))≠a(ϕ(v))](δB+2buvβ)},T^B=max{maxk,qLkq,maxvF^vB,BB/β}.

这里将跨核同步、往返搬运、关键路径和双 Pipe 负载放在同一 cycle 口径中；它没有模拟同时发起的 COPY 对共享 DDR 的竞争， 故 T^B 是排序代理而非官方 Makespan。

缓存项只作风险筛查。把某核子图按其给定顺序展开为一个拓扑操作序列， 记张量 t 在该核的首次产生或使用位置为 ftk， 最后使用位置为 ltk。对 r∈{L1,UB}， 将原图的 DDR 输入搬入位置按 UB 计，定义

(6.8)Hkr=maxj∑t:posk(t)=rbt1[ftk≤j≤ltk],RB=∑r∈{L1,UB}(maxkHkr−Cr)+.

该区间峰值忽略了附件 Step 1–2 的真实发射和换出决策； RB=0 不证明无溢出，RB>0 也不等于实际溢出字节。 它仅提示长期驻留导致的容量风险。最终内存可行性、实际峰值和 换入换出仍以未修改的原版评估程序核对。

有限切分候选与选择规则

问题二沿用分量装箱作为零割集候选，但按照场景 B 重算 通信和缓存项。对大连通图，补充一个宽度谷切分、两种 数据感知深度带宽度 wB,2wB 和一个固定深度带切分， 其中 wB 由当前图的分支/汇合层间距求得并限制在 [2,32]。这五个候选均只依赖本图结构； 重复候选按完整方案哈希去重。每个方案先查操作/子图覆盖和 合并后的依赖–核内顺序图无环，再计算式 （6.6）–（6.8）。 最终按

(6.9)JB=T^B+BB+10RBβ

排序，并以较小 BB 决定并列。式中 BB/β 是对 共享带宽压力的再校正，10RB/β 是同单位的缓存风险项。 全局系数 10 是先导实验中 28 个静态风险为正的方案上， 实际溢出字节与 RB 的比值中位数 10.54 取整所得， 并非每个用例独立拟合。该标定与最终验收使用同一批给定图， 因此不作为对其他图分布泛化能力的证明； JB 不是正式评价指标，不用于报告算法加速比。 五种有限构造避免逐候选调用原版评估器，尤其避免大图上 多轮官方模拟把求解时间推高。

算法 2　 场景 B 的通信–驻留联合筛选

**输入：**G，核数 N，原版固定配置；　**输出：**ϕ 与 (π1,…,πN)。

  1. 从当前图建立操作 DAG、张量生产/消费核关系与分支–汇合深度索引。
  2. 构造分量装箱、宽度谷、两种数据感知深度带和固定深度带共五类方案。
  3. 去重；检查非 COPY 操作覆盖、子图覆盖以及数据依赖与核内顺序的无环性。
  4. 对各合法方案计算 BB、T^B、Hkr 和 JB。
  5. 选 JB 最小者；若并列，取 BB 较小者；仅输出规定的两个 JSON 字段。

官方评估器只在方案冻结后的独立验收程序中运行，不参与以上选择。
